# Hope Bell — UX/UI-портфолио

Русскоязычный сайт-портфолио дизайнера Nadia / Hope Bell. Восемь страниц с учебными проектами AFTER, UNFOLD, FRAME и MindFlow, описанием задач, сценариев и визуальных решений.

[Открыть сайт](https://hopebluebell.github.io/hope-bell-portfolio/) · [Behance](https://www.behance.net/hopebell2) · [Telegram](https://t.me/hopesanxiety)

## Дизайн

Сайт свёрстан по окончательному макету автора из Figma. Сохранены тёплый светлый фон, насыщенные коралловые, розовые и фиолетовые фоны, чёрная антиква, крупные заголовки и сетка работ. Десктопная композиция адаптируется для узких экранов.

Проекты учебные. Сайт не приписывает им коммерческие запуски, подтверждённые исследования или измеренные бизнес-результаты. Данные внутри интерфейсов — демонстрационные.

## Технологии

HTML, CSS и JavaScript без фреймворков, сборщика, внешних шрифтов, трекеров и зависимостей в браузере. Статические страницы подходят для GitHub Pages и работают по прямым ссылкам, включая открытие кейсов в новой вкладке.

Локальный запуск:

```sh
python3 -m http.server 8000
```

Открыть `http://localhost:8000`. Для обычного редактирования сайта устанавливать пакеты не нужно.

## Оптимизация изображений

- 33 уникальных изображения, 91 WebP-вариант для разных экранов.
- `srcset` и `sizes` позволяют браузеру выбирать подходящий размер.
- У картинок указаны `width` и `height`, чтобы сохранять место до загрузки.
- Основная картинка страницы загружается приоритетно; остальные используют `loading="lazy"` и `decoding="async"`.
- Изображения отдельных кейсов не загружаются на главной. Полноразмерный вариант для увеличения открывается по нажатию.
- Текст страницы — HTML, а градиенты — CSS. Общий SVG макета размером 27 МБ не загружается посетителями.

Размеры и вес файлов перечислены в `assets/manifest.json`. Сравнение веса файлов не заменяет измерение скорости на реальном устройстве и соединении.

Для повторной обработки исходных JPEG нужен Python с Pillow:

```sh
python3 -m venv .venv
.venv/bin/pip install Pillow
.venv/bin/python scripts/optimize_images.py /path/to/source-images assets
```

Обрабатывать только изображения, которые используются на сайте. Варианты для новой картинки нужно добавить в соответствующий HTML: `src`, `srcset`, размеры и описание `alt`. Скрипт оптимизации перезаписывает манифест по выбранной исходной папке; сохраняйте полный набор исходников отдельно.

## Анимации и доступность

Реализован спокойный вариант: выезд основных блоков, экранов и карточек снизу при прокрутке, лёгкое изменение изображения при наведении. Анимации запускаются один раз и не задерживают навигацию.

Настройка устройства `prefers-reduced-motion` отключает движения и плавную прокрутку. Без JavaScript содержание остаётся доступным. Семантические заголовки, видимый фокус, ссылка перехода к содержанию, текущий пункт меню и описания изображений поддерживают навигацию с клавиатуры и экранным диктором.

Изображения в кейсах открываются в диалоге. Закрытие: кнопкой, клавишей Escape или нажатием на фон; после закрытия фокус возвращается к исходному изображению.

Другие варианты движения и предложения по развитию интерфейса: [UX/UI и анимации](UX-UI.md).

## Публикация

GitHub Pages: ветка `main`, папка `/ (root)`. Файл `.nojekyll` отключает обработку Jekyll. После изменений в основной ветке GitHub повторно публикует статический сайт. При переносе в другой репозиторий обновите ссылку сайта в этом README; внутренние ссылки относительные.

## Как редактировать

- Тексты и ссылки — в HTML соответствующей страницы.
- Цвета, отступы, мобильные правила — в `style.css`.
- Анимации появления и просмотр изображений — в `app.js`.
- Контакты повторяются в шапке, подвале и на странице контактов: изменяйте их во всех местах.

## Проверка

Перед публикацией проверены локальные ссылки, наличие изображений и корректность WebP-файлов. В Safari проверены главная на десктопе и при ширине 320/390 px, открытие кейса AFTER, переходы по разделам и диалог увеличения изображения. Проверка на физических Android/iOS-устройствах и измерение Lighthouse остаются отдельными проверками; баллы производительности не заявляются. Обновлённые цвета и полупрозрачный хэдер дополнительно проверены в Safari и Chrome, планшетный первый экран — при ширине 768 px, контакты и навигация — при ширине 320 px.

## Обновление интерфейса

Навигация подчёркивается малиновым акцентом при наведении, фокусе с клавиатуры и для текущей страницы. Фон закреплённого хедера имеет прозрачность 50%; текст и ссылки остаются полностью непрозрачными. Прозрачность реализована через RGBA, без зависимости от поддержки `backdrop-filter` или JavaScript.

Появление контента использует `IntersectionObserver`, прозрачность и смещение на 48 px. Для уменьшения движения и браузеров без поддержки наблюдателя контент остаётся видимым. Добавлены отдельные правила для промежуточных размеров планшетов и узких телефонов.
